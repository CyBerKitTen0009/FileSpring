# 架构与文件安全协议

## 已实现的边界

`src/filesystem.rs` 是 File Core：授权根目录、拒绝符号链接/Windows reparse point、普通文件快照、BLAKE3 校验、暂存文件、持久化和所有权检查。

`src/engine.rs` 是 Operation Engine：统一操作计划、整批预检、逐项执行、SQLite WAL/FULL 持久化日志、恢复、反向补偿。`src/model.rs` 是共享模型，CLI 与 GUI 调用相同接口。

`src/browser.rs` 提供非递归、256 条/批的目录流；单个文件元数据读取失败作为该项错误返回。CLI 不依赖 GUI 编译；GUI 是可选 feature。GUI 每栏使用有界通道、取消标记和独立扫描线程；耗时计划、复制、哈希和文本预览在串行后台工作线程执行。GUI 只建立可见行控件，仍会保存当前目录的全部条目，尚不是分页索引模型。

File Index、Automation、Asset Library、Processing、Sync & Backup 尚未实现；没有创建空模块或伪造入口。后续模块以 `Request → prepare → execute` 接入操作引擎，新增破坏性操作须先扩展恢复协议与测试。

## 授权与预演

引擎初始化时接受明确的根目录。状态目录受到排除保护。读取每段路径的链接元数据后再规范化；禁止 `..`、跟随链接、越界和操作恢复文件。授权根目录自身会规范化，根目录下的链接默认不跟随。

计划绑定源文件身份（设备/inode 或 Windows 文件 ID）、长度、修改时间和完整 BLAKE3 内容摘要。预演可读文件并写应用日志，不创建目标或暂存文件。已有目标、重复源、重复目标和相互依赖的重命名会阻止执行。非 Unicode 名称仍可浏览；JSON 日志 v1 拒绝其写操作，以免路径损坏。

执行前对整批 Pending 项重新检查身份、哈希、目标和空间；每项执行前再次校验。空间检查目前按目标父目录汇总，不能精确预测同一卷多个目标目录、配额、压缩或并发写入的实际可用空间；写入错误会停止并保留日志与恢复数据。

## 正向状态机

1. `Pending`：源文件与预演一致、目标不存在。
2. `Staging`：使用 `create_new` 在目标父目录建立唯一暂存文件，记录其身份，然后流式复制。权限、修改时间、内容和 `sync_all` 完成后生成暂存快照。
3. `Staged`：暂存快照持久化；通过 `hard_link(stage, destination)` 原子建立不覆盖的目标名。不支持硬链接时失败，不退回到可能覆盖的 rename。
4. `Published`：目标身份与暂存文件一致且内容验证通过。移动再检查源快照并移除源文件，Unix 上刷新父目录。
5. `Completed`：持久化完成状态后移除属于本操作的暂存名。

每次状态变更在 SQLite 事务中同时更新计划和追加事件。journal 为 WAL，`synchronous=FULL`；同一状态目录通过 OS 文件锁限制为单引擎。文件系统和 SQLite 是两个系统，没有跨二者的原子事务。

恢复不以“哈希相同”作为文件所有权的唯一证据。已经发布但尚未记日志的目标必须与已记录的暂存文件身份相同。未记录身份的暂存文件会保留供人工检查，而非静默删除。断电恰好发生在建立暂存名和记录身份之间时，可能需要人工检查并移走该暂存文件后继续。

## 撤销状态机

撤销前检查所有已完成目标；移动源原路径必须空闲。逆序处理已完成项目，未开始项目标记取消。

- 复制：先记录撤销意图，验证原目标快照，再移除本程序生成且未被修改的副本。
- 移动：先在原源目录进行校验复制、同步和不覆盖发布；记录 `Restored` 后才移除正向目标。最后标记 `RolledBack` 并清理所有权已验证的暂存名。

`rollback_requested` 持久化恢复方向，中断的撤销必须继续撤销，不会误继续正向操作。文件已被用户修改或重建时不覆盖、不猜测。部分执行后撤销可能先完成已开始的单个文件的恢复协调，再进行反向补偿。

## 尚未获得的保证

路径验证到文件使用之间存在 TOCTOU 窗口；尚未使用全平台句柄相对操作绑定每个父目录。针对不可信进程并发重命名目录的安全加固是 Phase 1 的剩余门槛。文件 ID 也可能被文件系统复用，内容与时间共同检查降低误认风险，但不构成永远不变的全局文件标识。

不支持递归目录操作、跨项目日志格式导入、覆盖恢复、删除、自动后台恢复或真正的版本备份。跨卷协议按复制→验证→删除设计，但当前没有第二个真实卷进行测试。Windows 目录 flush 能力与 Unix 不同，尚未实机验证断电持久性。硬件断电和真实设备断连未测试，进程中断测试不能代替这些测试。
